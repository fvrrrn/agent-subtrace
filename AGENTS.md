## 1. Обязательные правила

- Длительные shell-запуски должны показывать прогресс через tqdm: подготовка,
  кеширование, обучение и оценка. Это прямое требование пользователя.

- Не коммитить и не push; не писать тесты, не запускать линтер/форматтер без запроса.
- Не привлекать подагентов без прямого разрешения пользователя.
- Новые обучения, модели, повторы, сетки, калибровка и подбор порогов требуют
  отдельного разрешения. Наличие команды в коде не означает разрешения её выполнить.
- Не возобновлять остановленные эксперименты автоматически. Завершённые фоновые
  задачи не считать активными. Для ожидания использовать уведомления/pidfd,
  **не опрашивать completion**, если пользователь не запросил статус.
- Не изменять сторонний Kev и пользовательские `method.md`, `method_old.md`,
  `train/`, `todo/` без запроса. Не удалять/останавливать чужие данные и процессы.
- Старые source snapshots, метки, ошибки, неудачные прогоны и checkpoints сохранять.
  Изменения протокола — новая версия, не переписывание истории.
- Не показывать модели gold, rationale разметчика, будущие события или результат
  текущего проверяемого действия. Опубликованные мысли агента могут быть входом;
  объяснение внешнего оценщика — нет.
- Не обрезать входы, не применять окна/сводки молча. Отказы и исключения сохранять;
  сравнивать общие полностью оценённые случаи, явно сообщать их количество.
- Сохранять точные IDs/входы, logits, версии, weights/template/input hashes,
  фактические длины, kernel environment и затраты. Не считать score вероятностью
  вреда без проверки калибровки.
- Всегда различать AP, **трапецеидальную PR-AUC** и ROC-AUC. Для бинарных решений
  показывать precision/recall, F1, Accuracy и ложные тревоги; не скрывать низкий recall.
- Подбор по просмотренному benchmark — **post-hoc диагностика**, не held-out оценка.
  Внешние опубликованные числа отделять от наших измерений и проверять протокол.
- Не расширять работу по собственной инициативе: исследовательские идеи ниже
  не являются поручениями запускать новые эксперименты.

## 2. Исследовательская цель и смысл скоров

Цель — проверять безопасность действия с учётом истории: происхождения данных,
пользовательских разрешений, недоверенных инструкций и накопленных эффектов.
Последовательность допустимых действий может привести к запрещённой композиции.

Текущий подход: причинный Qwen выдаёт скрытое состояние **каждого токена**,
residual Mamba обновляет последовательное состояние, бинарная голова выдаёт score.
Нужен один forward целого диалога с несколькими размеченными действиями; состояние
сбрасывается между независимыми диалогами, не между действиями одного диалога.

Не отождествлять:
- опасность текущего действия, свидетельства атаки, возможность будущего вреда
  и уже реализованный ущерб;
- риск прочитанного префикса и распределение позиций токенов-свидетельств;
- token curve и интерпретируемую память/разделение нескольких угроз.

Монотонный рост не является универсальным законом вероятности вреда. Защитные
действия могут уменьшать возможность ущерба, нейтральные — не менять её.
Наши эксперименты — **replay записей**, не исполнение банковских/сетевых действий
и не измерение предотвращённого вреда.

### Архитектура и loss

- `Qwen/Qwen3.5-4B-Base@1001bb4d826a52d1f399e183466143f4da7b741b`.
- **Штатный `tokenizer.apply_chat_template`**, template SHA:
  `a4aee8afcf2e0711942cf848899be66016f8d14a889ff9ede07bca099c28f715`.
- `LN2560 → Linear2560→256 → 2×[x + Mamba2(LN(x))] → LN256 → Linear256→1`.
  Mamba2: state=64, expand=2, headdim=64, chunk=128, native CUDA/Triton.
- Один диалог — один forward, full BPTT, loss на всех известных action spans.
  Неразмеченная история не объявляется safe. **Не независимые prefix-примеры**.
- Token BCE: linear от предыдущей известной hard action-метки к текущей,
  начальный якорь 0. Это искусственная цель, не token gold. Среднее по токенам
  действия, затем по действиям диалога; accumulation — 4 диалога.
- `mono` — **междействийный**, НЕ потокенный:
  `0.1 mean relu(0.2 + z_early − z_late)` для соседних размеченных unsafe
  действий одного диалога, без пары через размеченный safe. `z` — raw endpoint logit
  из того же forward. Штраф не задаёт калибровку/тяжесть вреда.
- Четыре условия: frozen linear±mono, LoRA linear±mono; **по 2 эпохи**, seed=20261017.
  LoRA r=16, alpha=32, dropout=0, all-linear, non-reentrant gradient checkpointing.
  Fused AdamW: head lr=3e-4, LoRA lr=1e-5, wd=0.01, clip=1; Qwen bf16/SDPA,
  head fp32 с bf16 autocast. Выбор по hard endpoint validation BCE.
- Frozen disk cache учитывает IDs/weights/revision/template/environment, общий
  только для frozen. LoRA кодирует онлайн. Старые 0.8B/prefix features несовместимы.
  Это не реализованное incremental serving.
- CUDA gates проверили причинность, градиенты обоих Mamba/head/LoRA, маски loss,
  frozen hashes, reload и longest backward. Preflight ошибки v1/v2 сохранены;
  v3 переиспользует проверенный cache с безопасным TorchVersion metadata loader.

## 8. Новые гипотезы о форме кривой — пока без запусков

Пользователь под «тяжёлыми хвостами» понимает высокий уровень на обоих краях,
начало может быть выше конца. Предложена широкая немонотонная форма вместо linear.

CPU-only разбор 3 сконструированных предложений закреплённым Qwen tokenizer:
N = 21/26/28, evidence spans находятся в середине, правее середины и почти в конце.
Ручные веса субъективны, не token gold; примеры **не доказывают опасную середину**.
Графики и все IDs:
[token_position_priors_v1](graph-safety/artifacts/token_position_priors_v1/PROFILE_REVIEW.md).

Кандидаты: широкие truncated Normal/Student-t и смесь
`.60Uniform+.15Beta(1,2)+.25Beta(2,2)`. У последней peak-normalized форма
`g(u)=(.9+1.2u−1.5u²)/1.14`: начало 0.789, пик 1 при u=0.4, конец 0.526.
Это prior формы, **не инструкция выдавать risk=0.789 на любом первом токене**.
Высокий ранний риск требует видимого контекста; одинаковые causal prefixes с
разными продолжениями не могут надёжно иметь разные ранние gold risk scores.
Нормализованный номер i/N также зависит от ещё неизвестного онлайн N.

Распределение позиций `q_i=g_i/Σg` и peak-normalized risk shape — разные объекты:
q_i уменьшается как 1/N, прямое использование его как BCE risk target меняет шкалу.
Пользователь предложил weighted mean `Σw_i p_i/Σw_i`; это пока **только идея**:
может сгладить случайные пики, но разбавить короткий опасный фрагмент.
Позднее пользователь разрешил обучение выбранной кривой **вместе с event-loss**:
актуальный запуск указан в §3. Отдельные weighted-mean/Dice/readout-сетки и
другие формы кривых не назначены. Attention остаётся только отдельной идеей.

По просьбе искать идеи в других областях изучены weak-label sound event detection,
MIL в патологии, QA с no-answer и multiscale signal detection. Обзор источников,
формулы, градиенты и ограничения: [READOUT_IDEAS.md](graph-safety/READOUT_IDEAS.md).
Пока **только идеи**: shape-free linear-softmax MIL baseline; learned NULL против
latent contextual witness с event-BCE; статистический multiscale detector с safe
background. Нынешние prefix-risk scores нельзя считать независимыми evidence.
Event probability и token-localization следует различать; event-labels сами по
себе не идентифицируют истинные опасные токены. Из этого обзора теперь разрешены
только два условия §3, обязательно с token-curve BCE плюс event-BCE.

Новая идея пользователя: **causal attention→Mamba** либо **параллельные
Mamba/attention ветви с concat**; attention должен лучше извлекать релевантные
прошлые опасные события/токены. Записано в
[HISTORY_ATTENTION_IDEA.md](graph-safety/HISTORY_ATTENTION_IDEA.md), не включено
молча в согласовываемые readout-условия. Event-BCE может обучать обе ветви;
gold risk/dependencies нельзя подавать на вход attention. Явный risk bias
требует предсказанного upstream риска и causal mask, иначе цикл в схеме
attention→Mamba. Сохранять доступ к safe разрешениям/источникам; attention
heatmap не доказательство зависимости. Никаких attention-обучений пока нет.

## 9. Что важно помнить о прежних этапах

- Первоначально изучался LINK→SAFETY граф операционных зависимостей. Ребро означает
  использование результата/ресурса/указания, не автоматически угрозу или доказанную
  причинность. Возможны несколько родителей/переплетённые ветви. Новая архитектура
  маршрутизации угроз/GRU/банк механизмов не реализованы.
- Граф надо сравнивать с matched полным префиксом, не только с завершённой
  траекторией. Графовая подсказка и фильтрация истории — разные условия.
  Все предшественники проверялись, без принудительного top-k/разреживания.
- Старые графовые результаты не доказали устойчивого общего выигрыша. На R-Judge
  почти весь эффект sparse-hint возникал даже при пустом графе; на доступной части
  ATBench hint дал скромный прирост при низком абсолютном качестве и больших расходах.
- Синтетические примеры/ручные prompt-итерации и RRSI не являются независимым test.
  Laya могла постоянно отвечать safe, GLiClass — unsafe; Accuracy/F1 без матрицы
  ошибок здесь вводят в заблуждение.
- Лучший ранний ретроспективный результат R-Judge — Kev27B, AUC≈.942 на 569 общих
  записях, без нашего дообучения; это не доказательство пользы графа.
- Старые 0.8B `train_action_models.py` обучали независимые prefixes, а не текущий
  whole-dialog метод. Не приписывать им непрерывное обучение Mamba по целому trace.
- Исключение Complete из траекторного максимума может резко менять результаты.
  Primary/all-events, tool-only и matched sensitivity нельзя выбирать по лучшему числу.
- Старое Nemotron сравнение Kev имело 4544 OOM и 1022 negative-only общих случая —
  это **не валидный полный benchmark**. Наш adapter был final-report screening,
  не 100 полных traces из статьи StepGuard; security gold не бинаризируется произвольно.
- Исторические пути `/dev/shm/danefedov-*` теперь compatibility links и не являются
  постоянным хранилищем. Старые остановленные сетки/оценки не возобновлять.

## 11. Как обновлять этот документ

Заменять устаревшие состояния и сохранять полезные действующие ограничения.
Не дописывать сюда каждый PID, traceback, промежуточный процент или таблицу
полного sweep. Для отдельного запуска — protocol и артефакты; для истории — архив.
Предложения явно помечать как идеи, а не как уже выполненную реализацию.
Писать нормальными предложениями с пробелами между словами, числами и
сокращениями. Не сжимать текст склеиванием слов. Для краткости удалять повторы
и переносить детали в артефакты, сохраняя понятные формулировки и точные ссылки.
