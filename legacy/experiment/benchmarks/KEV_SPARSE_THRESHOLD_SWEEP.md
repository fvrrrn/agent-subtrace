# Kev-4B: сравнение порогов графовой подсказки

Пользователь попросил снизить чрезмерно строгий порог 0,80, затем явно поручил
проверить несколько порогов на каждой GPU `llm01`. Зафиксированы восемь вариантов:

| Физическая GPU | Последовательные пороги LINK |
|---|---|
| 0 | 0,30; 0,35 |
| 1 | 0,40; 0,45 |
| 2 | 0,50; 0,55 |
| 3 | 0,60; 0,65 |

По одному процессу эксперимента на карту; четыре очереди работают параллельно.
Все пороги и порядок заданы до новых запусков, без дальнейшего адаптивного
перебора. На GPU 0–2 присутствуют чужие процессы с небольшим потреблением памяти;
при проверке загрузка GPU была 0%, свободно более 75 ГБ на каждой. Они не
останавливаются. Скорость в таких условиях не является изолированным бенчмарком.

## Единственное изменение метода

Относительно [прогона 0,80](KEV_SPARSE_HINT_GRAPH.md) меняется только порог
допуска ребра: победитель не `NONE` и его возвращённый скор не ниже выбранного
значения. Промпт LINK, четыре класса, правило сохранения всей истории,
`<dependency_hint>`, вопрос SAFETY и порог нарушения 0,50 **не меняются**.
При точной ничьей действует прежний нативный приоритет `NONE`.

Каждый вариант заново обрабатывает все 571 записи закреплённого R-Judge,
проверяет все предшественники и измеряет полный префикс без подсказки как
контроль. Сохранённая ретроспективная классификация полной траектории не
вычисляется повторно. Для всех вариантов сохраняются точные входы, кодировки,
нативные скоры и логиты, рёбра, подсказки, ошибки, хеши и затраты. Обрезка
запрещена; прежние бюджеты 8192/512 и условия fp32/LoRA/температуры сохранены.

Этот диапазон выбран после просмотра предыдущего результата на том же наборе.
Поэтому сравнение — исследовательский подбор порога на уже изученных данных,
не независимая оценка выбранного лучшего варианта. Будут показаны все пороги,
а не только лучший. Низкий порог не доказывает точность рёбер; разметки
зависимостей по-прежнему нет. Пустые подсказки сохраняются во всех условиях.

## Расположение и воспроизведение

Код, неизменённые вспомогательные файлы и ссылки на данные/официальный Kev:
`/home/danefedov/kev4b-sparse-thresholds-20261013`.
Данные и веса не копируются заново и не изменяются.

На системном диске осталось около 1,7 ГБ. Поэтому полные артефакты создаются
в собственном каталоге `/dev/shm/danefedov-kev-sparse-thresholds-20261013`:
отдельный `threshold_XXX` для каждого порога. После каждого прогона результаты
и лог копируются в локальный
`experiment/benchmarks/results/kev4b_sparse_thresholds_20261013/threshold_XXX/`.
Содержимое `/dev/shm` неустойчиво к перезагрузке; локальные копии обязательны.

Пример для GPU 2 и порога 0,50 (остальные условия аналогичны таблице):

```bash
CUDA_VISIBLE_DEVICES=2 \
HF_HOME=/dev/shm/danefedov-kev-rjudge-20261013/huggingface \
HF_HUB_DISABLE_IMPLICIT_TOKEN=1 \
TRITON_CACHE_DIR=/dev/shm/danefedov-kev-rjudge-20261013/triton \
TRITON_F32_DEFAULT=ieee \
/dev/shm/danefedov-kev-rjudge-20261013/venv/bin/python -u \
  /home/danefedov/kev4b-sparse-thresholds-20261013/rjudge_kev_graph.py \
  --link-mode sparse-hint --link-threshold 0.50 \
  --output /dev/shm/danefedov-kev-sparse-thresholds-20261013/threshold_050
```

Итоговый аудит должен сравнить плотность и покрытие графов, траекторные метрики,
ложные тревоги и пропуски, изменения при пустых и непустых подсказках, затраты.
Совпадение LINK-скоров и полного префикса между порогами проверяется по
сохранённым выводам; изменения SAFETY с подсказкой требуют настоящего вывода
модели и не восстанавливаются перепорогованием старых траекторных скоров.

## Первые завершённые варианты: предварительное сравнение сетки

Завершены пороги 0,30; 0,40; 0,50; 0,60: каждый обработал все 571 записи
без ошибок. Это окончательные результаты этих четырёх вариантов, но пока
не итог всей сетки. Результаты копируются локально перед переходом к следующему
порогу на соответствующей GPU. Остальные четыре варианта затем остановлены
по прямому запросу пользователя; вся сетка не завершена.

| Порог LINK | Рёбра / 1558 | Плотность, % | TP | FP | F1, % | BA, % |
|---|---:|---:|---:|---:|---:|---:|
| 0,30 | 966 | 62,00 | 230 | 96 | 73,37 | 70,43 |
| 0,40 | 545 | 34,98 | 227 | 97 | 72,64 | 69,74 |
| 0,50 | 250 | 16,05 | 227 | 95 | 72,87 | 70,12 |
| 0,60 | 101 | 6,48 | 226 | 95 | 72,67 | 69,95 |
| Полный префикс без подсказки | — | — | 213 | 81 | 71,60 | 70,38 |

Менее строгие пороги увеличивают плотность, как и предполагалось. По BA
порог 0,30 среди этих вариантов близок к контролю (+0,046 процентного пункта),
остальные ниже. Во всех четырёх вариантах больше обнаружений и ложных тревог;
надёжное преимущество метода не установлено. Подробный парный аудит
всей сетки не выполнялся, поскольку пользователь остановил продолжение.

Отдельного дополнительного прогона 0,50 сверх этой сетки не запускается.
